# Вопросы жюри — Astana Walk

Отвечать за 20–30 секунд: сначала число или факт, потом причина. Не знаете — скажите, как проверили бы, и не называйте число наугад.

## RAG и модель

| Вопрос | Ответ |
|---|---|
| Где тут RAG, если поиск TF-IDF? | Retrieval — TF-IDF по 7 431 месту плюс признаки из отзывов. Затем проверки (часы на момент прихода, закрытия, путь по графу). Gemini получает до 9 кандидатов с фактами и выбирает 1–3 ID, пишет «почему» и «что делать». Генерация опирается только на найденный контекст. |
| Почему не эмбеддинги? | Запросы короткие, названия на RU/KK, много имён собственных. TF-IDF по символьным n-граммам ловит словоформы и опечатки, работает без GPU и без сети. Эмбеддинги можно добавить, но сначала нужна размеченная выборка, чтобы доказать прирост. |
| Как вы боретесь с галлюцинациями? | Модель не пишет факты. Цены, часы, минуты и маршрут кладёт backend. Модель возвращает JSON по схеме; ID не из контекста или битый JSON отклоняется, тогда работает локальный выбор. Покрыто тестами `test_model_rejects_invented_ids_and_hides_secrets`. |
| Что если Gemini недоступен? | Ответ строится из данных: те же места, «почему» и «что делать» по шаблону на языке запроса, с меткой «Из данных». Причина (нет ключа, HTTP 429) показывается пользователю. |
| Как вы извлекаете «тихо» и «розетки»? | 185 930 отзывов 2ГИС (первая страница, без авторов) → regex-фильтр 10 602 → Gemini классифицирует за/против и возвращает дословную цитату → если цитаты нет в отзыве, утверждение выбрасывается (43 отброшено в основном прогоне). Итог — признаки для 2 100 мест. |
| Насколько точна релевантность? | Размеченной оценки (nDCG на сотнях запросов) пока нет — это первый пункт плана. Сейчас: 14 сценариев с фактическими результатами в TEST_SCENARIOS.md, 66 автотестов backend, браузерные тесты. |

## Контекст и UX

| Вопрос | Ответ |
|---|---|
| Как учитывается время? | Бюджет из текста («30–60 минут» → 60, «1–2 часа» → 120). Путь по графу OSM (Dijkstra, 166 683 узла) + оценка времени на месте ≤ бюджета. Часы проверяются на момент прихода и всего визита. |
| Что с «открыто сейчас»? | Мы так не говорим. Только «открыто по опубликованному расписанию; праздничные изменения не проверены» или «часы не подтверждены». |
| Казахский язык? | Интерфейс RU/KK, казахские запросы распознаются («серуен», «сағат», «бала»). Шаблонные ответы без модели — на языке запроса. |
| Доступность? | Режим «Без лестниц» исключает отмеченные в OSM лестницы. Полную доступность для коляски мы не обещаем — нет данных о пандусах и входах. |

## Данные, этика, бизнес

| Вопрос | Ответ |
|---|---|
| Откуда данные и автоматизирован ли сбор? | 2ГИС Places API (4 500 записей), OpenStreetMap (2 941), Visit Astana (127), сайты площадок, афиша Ticketon. Сбор, нормализация, слияние дублей и извлечение признаков — скрипты в `collector/` и `scripts/`, запускаются в Docker. |
| Что вы храните о пользователе? | Ничего постоянного: нет аккаунтов, истории координат и логов чата. Геолокация только по кнопке. В Gemini уходит текст запроса и карточки, координаты не уходят. |
| Права на данные 2ГИС? | Отзывы хранятся локально, в репозитории только счётчики и короткие цитаты до 200 символов со ссылкой. Фото не копируются: загружаются с CDN 2ГИС при открытии карточки. Для публичного запуска нужен договор или официальный API. |
| Как зарабатывать? | Гипотезы, не выручка: пилот с порталом города и Visit Astana (B2G), виджет и API для отелей, аэропорта, ТРЦ (B2B), партнёрская комиссия с билетов на события. Платное размещение не меняет ранжирование и помечается. |
| Что не сделали? | Нет транспорта и пробок, нет живой проверки открытия, нет размеченной оценки релевантности, события не подтверждаются независимо. Всё это в плане развития. |

- Резервное видео демо на ноутбуке, PDF презентации на флешке.
