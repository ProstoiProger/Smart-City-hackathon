# Smart City Astana — полный список данных для сбора

**Проект:** Build with AI — «ИИ-помощник по прогулкам в городе Астана» (НИЦ Smart City).  
**Цель:** автоматизированный сбор POI для RAG-рекомендаций с учётом локации, предпочтений, доступного времени и контекста.

## Легенда
- **P0:** критично для MVP.
- **P1:** важно для качественного демо.
- **P2:** дополнительные возможности.
- **[ТЗ]:** поле указано непосредственно в задании.
- **[Расширение]:** рекомендовано для повышения качества, не является обязательным требованием организаторов.

## 1. Основные данные POI
- [ ] `poi_id` — уникальный идентификатор [P0; Расширение]

- [ ] `name_ru` — название на русском [P0; ТЗ: название]
- [ ] `name_kk` — название на казахском [P1; Расширение]
- [ ] `name_en` — название на английском [P1; Расширение]

## 11. Источники данных и способы сбора
| Источник | Назначение | Метод | Примечание |
|---|---|---|---|
| [OpenStreetMap](https://www.openstreetmap.org/) | Массовая база POI, координаты, теги, пешеходные пути | Overpass API / OSM-выгрузки | Соблюдать ODbL, атрибуцию и политику сервисов |
| [2GIS Places API](https://docs.2gis.com/en/api/search/places/overview) | Поиск и проверка отдельных организаций | Официальный API | Проверять ограничения на сохранение/использование |
| [Google Places API](https://developers.google.com/maps/documentation/places/web-service/reference/rest/v1/places) | Дополнительная проверка рейтингов, расписаний и статуса | Официальный API | Не строить постоянный датасет в нарушение условий |
| [data.egov.kz](https://data.egov.kz/) | Открытые государственные данные | Доступные API/выгрузки | Проверить актуальность и наличие нужных наборов |
| Официальные сайты POI | Билеты, описания, графики, доступность | Разрешённый парсинг / API | Сохранять URL и время проверки |
| Официальные афиши | Актуальные события | Разрешённый парсинг / API | Проверять отмену и изменение времени |
| [Open-Meteo](https://open-meteo.com/) | Погода | API | Использовать во время запроса |
| OSM + пешеходный роутер | Реальные дистанции и маршруты | GraphHopper / Valhalla / маршрутизатор с пешеходным профилем | Не подменять расстоянием по прямой |

## 12. Приоритетные пользовательские сценарии
1. **30–60 минут у Mega Silk Way:** ближайшие POI, время пешком, длина прогулки, погода.
2. **Тихое кафе с розеткой:** `quiet_place`, `power_outlets`, `wifi_available`, режим работы.
3. **Прогулка с ребёнком:** `playground`, `interactive_exhibits`, возрастные ограничения, цена.
4. **Турист за 2 часа до вылета:** ближайшие достопримечательности, длительность посещения, реальное время до аэропорта и запас на посадку.
5. **Ночная активность:** поздний режим работы, актуальные мероприятия, доступность и безопасность.

## 13. Ориентиры объёма (рекомендации, НЕ требования ТЗ)
- **1 500–3 000** очищенных POI.
- **200–300** особенно подробно описанных и проверенных POI.
- Координаты и категория — для всех POI.
- Описания — целевое покрытие 90–100%.
- Часы работы — целевое покрытие 80%+ среди объектов, к которым применимо расписание.
- Проверенные полезные теги — целевое покрытие 70%+.
- **30–50** тестовых запросов и **3–5** полноценных демо-сценариев.

## 14. Финальная проверка датасета
- [ ] Сбор данных реализован автоматизированными скриптами.
- [ ] Дубликаты и ошибочные координаты исключены.
- [ ] У каждого POI есть источник и дата обновления.
- [ ] Неизвестные часы работы не трактуются как «сейчас открыто».
- [ ] Факты источников отделены от сгенерированных описаний и оценок.
- [ ] Учитываются реальные пешеходные маршруты, время и ограничения.
- [ ] Использование, хранение и показ данных соответствуют лицензиям и API-условиям.
- [ ] Координаты пользователей не сохраняются без необходимости.
