# Astana Walk — Smart City

Готовый локальный прототип для задачи Smart City: карта Астаны, поиск, чат с Gemini, карточки с источниками и признаками из отзывов 2ГИС и пешеходные маршруты. Единственная языковая модель — Gemini API; без ключа работает детерминированный поиск.

> **После `docker compose up -d --build` откройте:**
>
> | Что | Ссылка |
> |---|---|
> | Приложение (карта, список, чат) | **[http://127.0.0.1:8090](http://127.0.0.1:8090)** |
> | Swagger — документация API | [http://127.0.0.1:8090/docs](http://127.0.0.1:8090/docs) |
> | Проверка готовности | [http://127.0.0.1:8090/api/health](http://127.0.0.1:8090/api/health) |
> | Dev-сервер интерфейса (только `docker compose --profile dev up web`) | [http://127.0.0.1:5180](http://127.0.0.1:5180) |
>
> Порт 8090 занят — запустите `APP_PORT=8091 docker compose up -d` и откройте http://127.0.0.1:8091.

В репозитории: исходники backend и frontend, 7 570 исходных POI и 7 431 каноническая запись после слияния, компактный пешеходный граф OSM, поисковый индекс, признаки из отзывов 2ГИС, сборщики данных, тесты и Docker-окружение. Схема «карта + список + чат» взята из проекта AFM_project; его жилищные данные, юридические ответы и строительные рейтинги не используются.

## Быстрый старт (Docker)

Нужен только Docker с Compose v2 (Docker Desktop на Windows/macOS или Docker Engine на Linux). Python и Node.js ставить не нужно.

```bash
cp .env.example .env          # впишите GEMINI_API_KEY; без ключа работает поиск без модели
docker compose up -d --build
```

Откройте **[http://127.0.0.1:8090](http://127.0.0.1:8090)**. Первая сборка занимает несколько минут: образ собирает интерфейс (проверка типов и переводов) и ставит зависимости Python.

| Действие | Команда |
|---|---|
| Логи | `docker compose logs -f app` |
| Перезапуск после правки `.env` | `docker compose up -d` |
| Остановить | `docker compose down` |
| Другой порт (если 8090 занят) | `APP_PORT=8091 docker compose up -d` |

Контейнер работает от непривилегированного пользователя, проверяет себя через `/api/health` (статус `healthy` в `docker compose ps`), а `.env` в образ не попадает: Compose передаёт его при запуске. Карте нужен интернет для подложки OSM, чату — доступ к Gemini API.

## Gemini API

Откройте `.env` **в папке приложения рядом с run.py** и заполните:

```dotenv
LLM_PROVIDER=gemini
GEMINI_API_KEY=your_key_here
GEMINI_MODEL=gemini-3.6-flash
GEMINI_THINKING_LEVEL=low
```

Примените изменения: `docker compose up -d`. Ключ остаётся на сервере и не попадает во frontend. Gemini 3 по умолчанию «думает» на уровне `high`, и ответ занимает десятки секунд. Для выбора мест и коротких объяснений достаточно `low`.

**Квоты.** На бесплатном тарифе Google даёт около 20 запросов в сутки на flash-модель, а запросы могут использоваться для улучшения продуктов Google. Для демо и извлечения признаков привяжите платёжный аккаунт в AI Studio (Tier 1): лимиты станут выше, а данные запросов не будут использоваться для обучения. При ошибке, исчерпанной квоте или отсутствии ключа чат показывает причину и отвечает локальным поиском.

Использован REST `generateContent` со структурированным JSON-ответом. Документация: [Gemini Generate Content](https://ai.google.dev/api/generate-content), [structured output](https://ai.google.dev/gemini-api/docs/generate-content/structured-output), [rate limits](https://ai.google.dev/gemini-api/docs/rate-limits).

## Как работает RAG

0. **Разбор запроса** (`backend/query.py`, без модели). Из текста берутся: старт или цель («я у Экспо» — старт, «сходить в Хан Шатыр» — цель, старт с карты сохраняется), бюджет («30–60 минут» → 60, «полчаса», «1–2 часа»), время суток («вечером», «ночью», если время не задано), «рядом» (до 15 мин пешком), несколько видов мест («музей и кофе»). Всё, что учтено, ответ показывает в блоке «Учтено» — пользователь видит, на каких данных построена выдача.
1. **Retrieval.** TF-IDF по названиям, описаниям, категориям и атрибутам находит кандидатов. Служебные слова запроса («хочу», «где», «можно») в лексический поиск не идут, иначе «хочу…» находит кафе «Хочу хинкали». Названное в запросе место получает приоритет. В поисковый документ места добавляются признаки, подтверждённые отзывами.
2. **Контекст.** Backend исключает закрытые места и проверяет расписание на время прибытия и всего визита, бюджет времени и путь по пешеходному графу. Из запроса распознаются нужные свойства: розетки, тишина, работа с ноутбуком, Wi-Fi, дети, интерактив, доступность, вид. Они влияют на ранжирование и предупреждения.
3. **Генерация.** Gemini получает запрос, контекст (бюджет, погода, размер компании, события) и факты до 9 кандидатов, включая сводку отзывов. Он выбирает 1–3 **существующих ID** и пишет «почему» и «что делать». Посторонние ID и некорректный JSON отклоняются, тогда используется локальный выбор. Без модели (нет ключа, квота, сеть) «почему» и «что делать» собираются по шаблону из полей места на языке запроса (RU/KK/EN) и помечаются «Из данных».
4. **Мини-маршрут.** Если запрос про прогулку или маршрут («погулять», «маршрут», «серуен», «walk») или включён переключатель «Мини-маршрут из 3 мест», backend сам выбирает до 3 мест и их порядок: перебирает последовательности из 16 лучших кандидатов по пешеходному графу, проверяет, что дорога, посещения и часы работы на момент прихода вместе укладываются в бюджет, и предпочитает разнообразные остановки (не три одинаковых объекта подряд). Если 3 места не помещаются, остаются 2. Gemini получает готовый порядок и пишет «почему» и «что делать» под время каждой остановки; маршрут сразу рисуется на карте.
5. **События.** Анонсы из `data/events.jsonl` (театр, концерты, стендап, выставки, детские) отбираются по времени прогулки и пешей доступности: сеанс должен начаться во время прогулки, и до него нужно успеть дойти по графу; выставки с диапазоном дат учитываются, пока идут; отменённые, прошедшие и распроданные анонсы пропускаются. При запросе про концерт, спектакль или выставку площадки событий попадают в кандидаты, а Gemini называет событие и время начала; в остальных случаях показываются события не дальше 20 минут пешком. Это опубликованные анонсы, не подтверждение проведения.
6. **Компании из 3–5 человек.** Размер компании берётся из «Условий прогулки» («Сколько вас») или из текста («нас 4», «втроём», «с друзьями», «бесеуміз»). Выше поднимаются места с опубликованными в 2ГИС «VIP-зал», «Кабинки», «Проведение банкетов», «Корпоративные обеды»; у кафе для 4+ человек — совет забронировать стол; бюджет пересчитывается на всех по опубликованной цене за одного (билет или средний чек).
7. **Честная маркировка.** Цены, часы, расстояния и маршруты на карточках строятся backend из данных: модель их не пишет. Текст модели помечен «Текст: Gemini», для него указано, на чём он основан (данные места, отзывы, время пути, расписание, погода). «Что делать» — идея, а не проверенный факт.

Текст запроса и найденные карточки передаются Gemini. Точные координаты пользователя не передаются. Если пользователь сам написал адрес в сообщении, этот текст входит в запрос к модели.

## Признаки из отзывов 2ГИС

`collector/scripts/collect_reviews.py` собирает первую страницу публичных отзывов по 4 717 филиалам: текст, оценку и дату, без данных авторов. Тексты лежат только локально в `collector/output/` и в репозиторий не попадают.

`scripts/extract_review_signals.py` обрабатывает их в три шага:
- регулярное выражение отбирает отзывы, где может упоминаться нужное свойство;
- Gemini классифицирует каждое упоминание (за / против / смешанно) и возвращает дословную цитату;
- утверждение сохраняется, только если цитата действительно есть в отзыве.

Итог по каждому месту записывается в `data/review_signals.jsonl`: число упоминаний «за» и «против», дата последнего и до трёх коротких цитат. Статусы:

| Статус | Условие |
|---|---|
| `supported` | ≥2 «за» и «против» не больше трети |
| `single_mention` | одно упоминание |
| `mixed` | отзывы расходятся |
| `contradicted` | «против» больше |

Фильтр «Только подтверждённые удобства» пропускает данные места или `supported` из отзывов. В карточке это помечено «по отзывам 2ГИС», а не как проверенный факт.

Оба шага запускаются в контейнерах профиля `data`; результаты пишутся в примонтированные `collector/output/` и `data/`:

```bash
docker compose --profile data run --rm reviews                                   # отзывы 2ГИС, 1 запрос/с, с продолжением
docker compose --profile data run --rm reviews -m scripts.collect_reviews --pilot 10
docker compose --profile data run --rm signals                                   # извлечение признаков через Gemini
docker compose --profile data run --rm signals python scripts/extract_review_signals.py --limit-reviews 120
docker compose --profile data run --rm signals python scripts/extract_review_signals.py --aggregate-only
docker compose up -d --build                                                     # пересобрать приложение с новыми признаками
```

## Фото мест

Фото не хранятся в данных и не скачиваются заранее. Когда пользователь открывает карточку, интерфейс запрашивает `/api/pois/{id}/photo`: backend по ID филиала 2ГИС проверяет главное фото на CDN 2ГИС (тот же адрес, что Places API отдаёт в `external_content[].main_photo_url`) и кэширует ответ (найдено — 7 дней, нет фото — сутки, сбой сети — 5 минут). Браузер загружает картинку напрямую с CDN, в карточке подпись «Фото: 2ГИС» со ссылкой на организацию. У мест без филиала 2ГИС (OSM, Visit Astana) фото нет.

## Поиск

Сохранённый TF-IDF индекс по символьным n-граммам (`data/indexes/tfidf.joblib`) пересобирается автоматически при изменении текстов. Локальные нейросетевые модели не используются. Загружайте только доверенные локальные файлы `joblib`.

## Маршруты и ограничения данных

- Граф содержит 166 683 узла и 391 338 направленных рёбер из собранного снимка OSM. Используется Dijkstra, не расстояние по прямой вместо маршрута.
- Начало и конец привязываются к ближайшим узлам основной пешеходной сети на расстоянии до 150 м (радиус меняется ползунком в «Условиях прогулки», 30–300 м): у крупных зданий вроде Хан Шатыра центр находится в 80–130 м от улицы, а изолированные дорожки внутри зданий не используются. Эти соединения не проверены; время на них учитывается отдельно. Физическая доступность входов не гарантируется.
- Режим «Без лестниц» исключает отмеченные лестницы. Он не подтверждает доступность для коляски, наличие пандусов и качество покрытия.
- Маршрут из 1–3 мест строится последовательно в пределах времени, без обратного пути. Алгоритм жадный, не гарантирует глобально оптимальный тур.
- Часы сравниваются в часовом поясе Астаны UTC+5. «По расписанию открыто» не означает проверенное открытие в реальном времени. Праздничные изменения неизвестны.
- 185 свежих отметок 2ГИС о временном закрытии/скором открытии перенесены в данные приложения. Отсутствие отметки не доказывает, что место открыто.
- В данных **нет полных цен, правил и сведений о закрытиях по всем заведениям**. Пропуски не заполняются догадками. Средний чек отличается от стоимости входа.
- «Тихо», «розетки» и другие удобства считаются подтверждёнными только при поле данных места или повторяющихся утверждениях в отзывах (`supported`); одно упоминание показывается как неподтверждённое. Строгий фильтр «Только подтверждённые удобства» может дать пустой результат.
- Перед рейсом пользователь должен указать время дороги в аэропорт и резерв на аэропортовые процедуры. Они вычитаются из бюджета; без них чат не предлагает прогулку. Это введённые пользователем оценки: транспорт в реальном времени и требования конкретного рейса не подключены. Погода запрашивается у Open-Meteo для центра Астаны с кэшем на 5 минут; это актуальная оценка погодной модели, не измерение у заведения. При сбое старый снимок не выдаётся за текущую погоду.
- Данные собраны 19 октября 2026; источники могут содержать более старые сведения. Это снимок для демо, а не мониторинг заведений.

## Разработка и проверки

Всё запускается в контейнерах; профили Compose: `test`, `dev`, `data`.

```bash
docker compose --profile test run --rm tests             # backend: pytest (модель замокана, ключ не нужен)
docker compose --profile test run --rm collector-tests   # тесты сборщиков данных
docker compose --profile test run --rm e2e               # Playwright: сценарии + axe (светлая/тёмная, RU/KK, десктоп/мобильный)
docker compose --profile dev up web                      # Vite с горячей перезагрузкой: http://127.0.0.1:5180 (порт: `WEB_PORT`)
```

`e2e` поднимает приложение, ждёт `healthy` и гоняет браузерные тесты в официальном образе Playwright; скриншоты сохраняются в `qa/`. `web` монтирует `frontend/` и проксирует `/api` в контейнер `app`, так что правки интерфейса видны сразу. Сборка `npm run build` внутри образа падает, если у строки интерфейса нет перевода RU/KK или в разметке осталась жёстко прописанная кириллица.

Цели `Dockerfile`: `ui` (сборка интерфейса), `app` (рабочий образ), `dev` (+ тесты и скрипты), `collector` (сборщики со своими зависимостями).

## Структура

- `backend/`: FastAPI, поиск, расписание, провайдеры, маршрутизация.
- `frontend/src/`: исходники React/TypeScript/Leaflet.
- `frontend/dist/`: готовая production-сборка (образ собирает её заново).
- `Dockerfile`, `docker-compose.yml`: образы и сервисы приложения, тестов, dev-сервера и сбора данных.
- `data/`: исходные и канонические POI, атрибуты с источниками, таксономия, журнал слияний, 103 записи событий, граф, индексы и манифест.
- `scripts/prepare_data.py`: офлайн-конвертация исходного датасета сборщика в формат приложения; принимает `--source <папка data сборщика>` с `processed` и `raw`.
- `tests/`, `frontend/tests/`: API и браузерные проверки.
- `collector/`: код исходного сборщика, его тесты и образец настроек. Для повторного сбора нужны собственные ключи и источники; сырые сетевые кэши не включены. Приложение уже содержит готовые данные и индексы.
- `HACKATHON.md`: сценарии демонстрации, архитектура и соответствие задаче.
- [`TEST_SCENARIOS.md`](TEST_SCENARIOS.md): тестовые сценарии с фактическими результатами, работа с неполными данными, ограничения, этика и приватность.
- `NOTICE.md`: источники и ограничения происхождения данных.
- `qa/`: скриншоты и результаты проверки поставки.
- `presentations/`: презентация для жюри (PDF, PPTX, исходник `astana_walk.md`), текст выступления, ответы на вопросы и скрипт скриншотов `capture_screens.py`.

Это прототип для задачи Smart City. Он не включает CampusPulse/MCP/Vertex AI Agent Engine и не заявляет соответствие второй задаче PDF.

## Исправления качества RAG

- `source_pois.jsonl` сохраняет все 7 570 исходных записей. В `pois.jsonl` — 7 431 каноническая запись: 141 слияние, плюс аэропорт как контекстная точка и отдельный океанариум Ailand.
- MEGA Silk Way и Qazaq Gourmet объединены с сохранением описаний, рейтингов, источников и исходных ID. 124 неоднозначные пары оставлены в `dedup_candidates.jsonl`; близость сама по себе не доказывает совпадение филиалов.
- Геометрии двух OSM-записей Президентского парка проверены: полигоны не пересекаются. Они сохраняются раздельно; это проверка картографических объектов, а не доказательство административного статуса парков. Результат — `data/president_park_geometry_review.json`.
- Сведения 2ГИС из 4 610 исходных записей включены как `provider_attributes` с URL/датой. Читаемые значения попадают в индекс; платежные атрибуты не загромождают семантическое представление.
- 122 исходных значения подкатегорий приведены к 91 коду. Например `cafe`/«Кафе», `museum`/«Музеи», `mall`/«Торговые центры» имеют общие коды. Исходные значения сохраняются.
- 1 621 безымянная запись сохранена для происхождения и инфраструктуры, но исключена из рекомендаций. Адреса, шаблонные описания и сырые `key=value` теги исключены из семантических документов. Поэтому «Байтерек» не становится запросом по сотням адресов.
- Приоритет точного имени выше совпадения описания. Рейтинг получает небольшой сглаженный вклад с учётом числа оценок; это не обученная модель качества. Параметры prior 4.5 / 245 явно записаны в отчёте.
- Хазрет Султан находится и под казахским названием. На казахской странице Visit Astana опубликовано ежедневное расписание 06:00–20:00; оно добавлено с источником. Альтернативное старое утверждение 24/7 сохранено как конфликт. Фактическое открытие и праздничные изменения не проверены.
- Закрытый Музей энергии будущего Нур Алем не подменяется работающим музеем. Чат объясняет закрытие и отдельно использует сведения alem.ai.
- Океанариум Ailand / Думан добавлен отдельной карточкой с расписанием оператора; координата привязана к родительскому комплексу, точный вход неизвестен. Тарифы других аттракционов не переносятся.

Из опубликованных атрибутов собраны 4 863 содержательных описания с меткой `attribute_grounded_summary`: это составленные по фактам тексты, не новые независимые отзывы. У 748 канонических записей есть конкретные сведения о детских удобствах, у 2 610 — сведения о цене/среднем чеке, у 1 398 — опубликованные ограничения. Средний чек, тариф и ценовой документ сети различаются. Доступный вход не выдаётся за доступность всего здания.

Океанариум: опубликованные билеты «Стандарт» 5 600 ₸ и детский 4 400 ₸ взяты из карточек оператора. Возрастные границы неизвестны, «Стандарт» не переименован во «взрослый». Цены не переносятся на остальные аттракционы комплекса.

Группировка одноимённых близких филиалов подавляет повторные рекомендации, не сливает их цены и свойства. 76 объектов имеют явные ограничения доступа и исключены из рекомендаций.

В афише 103 календарные записи, а не 103 уникальных фестиваля. У каждой записи — ссылка на страницу билетов Ticketon (или издателя). Автоматическая проверка страниц издателя (`scripts/recheck_events.py`) не подтвердила ни одного события: 101 запись — источник недоступен для запроса, 2 — неподдерживаемый издатель; поэтому кнопки проверки в интерфейсе нет. Афиша остаётся снимком публикаций, без обещания актуальности.

Отчёты: `data/quality_report.json`, `qa/REMEDIATION_REPORT.md`, `qa/VALIDATION.md`. По всем объектам выполнен аудит имеющихся источников; полнота всех цен, правил, розеток, тишины и закрытий **не достигнута**. Для 7 411 записей сохранён список недостающих полей и источников в `data/missing_data_backlog.jsonl`. Наличие атрибутов не превращает их в независимую проверку на месте.
