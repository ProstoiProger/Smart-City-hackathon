# API

Все пути начинаются с `/api`. Backend и frontend в production работают с одного origin. Swagger: `/docs`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | /health | Готовность и число POI |
| GET | /weather | Текущая модельная погода Open-Meteo, 5 минут кэша |
| GET | /events | Календарный снимок; будущие/текущие записи, исключая явно отменённые/перенесённые |
| GET | /meta | Категории, опорные точки, настройки без ключей |
| POST | /search | Поиск и проверка пути/расписания |
| GET | /pois/{poi_id} | Карточка с источниками |
| GET | /pois/{poi_id}/photo | Главное фото 2ГИС: проверяется только при открытии карточки, ответ кэшируется |
| POST | /chat | RAG: Gemini выбирает до трёх мест и пишет «почему» / «что делать» |
| POST | /plan | Последовательный маршрут |
| POST | /replan | Перестройка прогулки на ходу: «здесь закрыто», «+15 минут», «замёрзли», «устали» |

Пример `/chat`:

```json
{"query":"Где погулять 60 минут возле MEGA Silk Way?","provider":"offline","minutes":60,"when":"2026-10-19T12:00:00+05:00","open_only":false,"no_steps":false,"strict_amenities":false}
```

Общие поля: `latitude`, `longitude` (обе либо ни одной), `minutes` (10–240), `when` (ISO 8601, без смещения интерпретируется как UTC+5), `no_steps`, `max_snap_m` (30–300, по умолчанию 150: насколько далеко от пешеходной сети могут быть старт и места; задаётся ползунком в «Условиях прогулки», границы приходят в `/api/meta` → `snap_radius_m`). Для поиска: `query`, `category`, `open_only`, `strict_amenities`, `limit` (1–100). Для чата: `provider` = offline/gemini. Для плана: `poi_ids` (1–3). План требует координат начала.

В `/chat` место, названное как точка старта («я у/возле/от MEGA», «Хан Шатыр жанындамын»), имеет приоритет над координатами выбранного старта; в интерфейсе возвращённое начало отображается на карте. Место, названное как цель («сходить в Хан Шатыр», «идём в Столичный цирк»), старт не меняет: оно становится первым кандидатом со своим маршрутом, а если в запросе больше ничего не просят — единственным. Без координат старта первое названное место задаёт район поиска. Опорные точки: MEGA, Байтерек, Национальный музей, Астана Опера, alem.ai, EXPO 2017.

Чат также читает из текста: время («30–60 минут» → верхняя граница 60, «полчаса», «полтора часа», «1–2 часа», «пару часов»), время суток, если `when` не задан («вечером» → сегодня с 18:00, «ночью» → с 22:00, «утром», «днём», «завтра»), «рядом/недалеко/поблизости» (пешком до места не больше 15 мин, при нехватке мест или удобств — 25 мин; не в режиме маршрута), несколько видов мест через «и/или/затем» («музей и кофе»: кандидаты каждого вида, маршрут включает каждый вид). Служебные слова («хочу», «где», «можно») не участвуют в лексическом поиске.

Расстояния и время приблизительные. `route.duration_min` включает предположительную длительность соединений с графом; `network_duration_min` и `network_distance_m` относятся только к графу. `door_to_door_verified` всегда false. Неизвестные поля POI — null.

Старые ID объединённых мест разрешаются через `poi_aliases.json`. План удаляет повторные ссылки на одну каноническую запись.

Для `/chat` перед рейсом передайте `airport_transfer_min` и `airport_reserve_min` (каждое 0–240): введённые пользователем оценки дороги и процедур. Чат вычитает их из общего времени. Если значений нет, используется явное допущение 30 мин дороги + 60 мин в аэропорту: ответ и предупреждение говорят об этом и предлагают указать свои значения (`flight_context.buffers_source` = `default_assumption`, `needs_buffers` = true). Если после резервов остаётся меньше 10 минут, прогулка не предлагается. Прогноз пробок/требования авиакомпании не подключены.

Карточка различает `standard_ticket_price`, `child_ticket_price`, `adult_ticket_price`, `ticket_options`, опубликованные `pricing` и средний чек. Документы сети/комплекса помечаются неподтверждёнными для конкретного филиала. `entrance_accessible` отдельно от полной `wheelchair_accessible`; отзыв о тишине хранится как ограниченное утверждение, не проходит строгий фильтр.

Живой проверки анонсов в API нет: страницы издателей (Ticketon) не отдаются автоматическому запросу, поэтому интерфейс показывает ссылку на страницу билетов. Офлайн-скрипт `scripts/recheck_events.py` сохраняет попытки проверки в `publisher_recheck`; отсутствие доступа/данных не считается подтверждением, и даже опубликованное `EventScheduled` не является независимой проверкой проведения.

Ответ `/chat`: `considered` — список `{label, value}` того, что учтено (старт и откуда он взят, бюджет, время, лимит «рядом», категории и удобства из запроса, место-цель, компания, фильтры, резервы на вылет, мини-маршрут); `when` — использованное время начала (`null` = сейчас). У каждого места есть `why` и `what_to_do` (текст Gemini, а без модели — шаблон из данных места на языке запроса), `explanation` (`generated`, `template`, `basis` — данные места/отзывы/время пути/расписание/погода, `note`), `evidence` (для свойств из запроса: `confirmed`, `supported`, `single_mention`, `mixed`, `contradicted`, `unknown`) и `review_signals` (счётчики и короткие цитаты отзывов 2ГИС). Поле `group_size` (1–10; в `/api/search` и `/api/chat`) задаёт размер компании, иначе чат определяет его по тексту; в ответе чата `group` (`size`, `from_text`), у мест — `group_cost` (`size`, `amount`, `currency`, `basis`: `adult_ticket`, `standard_ticket`, `average_check`, `free_entry`). `events` в ответе чата — анонсы во время прогулки в пешей доступности (`name`, `start`, `end`, `timed`, `venue`, `venue_poi_id`, `walk_min`, `late`, `price_from`, `age_group`, `source_url`); `late` = true только для площадки-цели запроса: к началу пешком не успеть, ответ говорит об этом; у мест-площадок те же записи в `events`. Поле запроса `mini_route` (`true`/`false`, по умолчанию — по смыслу запроса) включает мини-маршрут; в ответе `mini_route` содержит `stops` (с `arrival_offset_min` — через сколько минут от старта прибытие), `legs` (пешие отрезки с геометрией), `total_duration_min`, `walk_duration_min`, `budget_minutes`, `covers_requested` (все ли названные виды мест вошли), а `items` идут в порядке маршрута. При тесном бюджете визит в остановку может быть сокращён до минимума категории (`visit_shortened`, `typical_visit_min`). `generated_text` показывает, использовался ли текст модели; `generated_facts` всегда false.

**Финиш и срок.** Если в тексте сказано, где нужно оказаться («через час нужно быть в MEGA», «к 15:00 в Хан Шатыр», «вернуться к началу»), или в запросе заданы `finish_latitude`/`finish_longitude`/`finish_label` либо `finish_loop: true`, чат строит маршрут старт → остановки → финиш: последний отрезок и запас (`finish_reserve_min`; из текста «с запасом 5 минут», иначе 10 мин, для круга 0) входят в бюджет. Время «к 15:00» задаёт бюджет от времени начала. В `mini_route.finish`: `label`, `latitude`, `longitude`, `loop`, `leg` (отрезок до финиша), `arrival_offset_min`, `arrival_at`, `deadline_at`, `reserve_min`, `slack_min`, `fits` (успевает ли с запасом). Если остановка не помещается, `stops` пуст, а ответ честно говорит, хватает ли времени на прямой путь пешком. `mini_route.session` — состояние для `/replan`: `query`, `start_at`, `start`, `budget`, `finish`, `reserve`, `category`, `group_size`.

**`POST /replan`.** Клиент присылает `session` из чата и ход прогулки: `position` (где пользователь), `elapsed` (минут от начала), `keep` (оставшиеся остановки по порядку), `visited`, `excluded`, `flags` (`indoor`, `rest`), `action`: `closed` (следующая остановка `stop_id` закрыта — исключается и заменяется), `delay` (+`delay_min`, по умолчанию 15), `cold` (дальше только места под крышей, переходы до 10 мин), `tired` (на одну остановку меньше, переходы до 8 мин, выше кафе и тихие места). Сервер пересчитывает остаток с теми же проверками графа и часов работы, сохраняя финиш и срок. Ответ: `answer`, `plan` (как `mini_route`, времена от начала всей прогулки), `changes` (`removed`, `added`), `state` (новые `elapsed`, `position`, `excluded`, `visited`, `flags`, `now`, `remaining_min`).

## Дополнительные точки

| Метод | Путь | Что |
|---|---|---|
| POST | `/api/chat` | Новые поля запроса: `members` (до 6 участников `{name, wish}`, режим группы). Новые поля ответа: `comfort`, `funnel`, `rejected`, `group`; у мест `exposure`, `comfort`, `group_fit`. |
| GET | `/api/weather` | Теперь с блоками `air` (AQI, PM2.5) и `comfort` (факторы погоды и воздуха). |
| POST | `/api/pois/{id}/ask` | `{question, when?}` → `answers[]` с `certainty` (`yes`/`likely`/`unknown`/`no`) и `evidence[]`. |
| GET | `/api/tours?lang=` | Список прогулок с гидом. |
| GET | `/api/tours/{id}?lang=` | Точки с фактами и источниками, участки пути по графу OSM. |
| GET | `/api/city/audit` | Карта пробелов города (404, пока не собрана). |
| GET | `/api/events` | Добавлены `live_collected`, `live_collected_at`. |
