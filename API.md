# API

Все пути начинаются с `/api`. Backend и frontend в production работают с одного origin. Swagger: `/docs`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | /health | Готовность и число POI |
| GET | /weather | Текущая модельная погода Open-Meteo, 5 минут кэша |
| GET | /events | Календарный снимок; будущие/текущие записи, исключая явно отменённые/перенесённые |
| POST | /events/{event_id}/refresh | Проверка опубликованного статуса по странице разрешённого издателя, кэш 15 минут |
| GET | /meta | Категории, опорные точки, настройки без ключей |
| POST | /search | Поиск и проверка пути/расписания |
| GET | /pois/{poi_id} | Карточка с источниками |
| POST | /chat | RAG: Gemini выбирает до трёх мест и пишет «почему» / «что делать» |
| POST | /compare | Сравнение до трёх мест |
| POST | /plan | Последовательный маршрут |

Пример `/chat`:

```json
{"query":"Где погулять 60 минут возле MEGA Silk Way?","provider":"offline","minutes":60,"when":"2026-10-19T12:00:00+05:00","open_only":false,"no_steps":false,"strict_amenities":false}
```

Общие поля: `latitude`, `longitude` (обе либо ни одной), `minutes` (10–240), `when` (ISO 8601, без смещения интерпретируется как UTC+5), `no_steps`, `max_snap_m` (30–300, по умолчанию 150: насколько далеко от пешеходной сети могут быть старт и места; задаётся ползунком в «Условиях прогулки», границы приходят в `/api/meta` → `snap_radius_m`). Для поиска: `query`, `category`, `open_only`, `strict_amenities`, `limit` (1–100). Для чата: `provider` = offline/gemini. Для сравнения/плана: `poi_ids` (1–3). План требует координат начала.

В `/chat` явно названная опорная точка, например MEGA, имеет приоритет над координатами выбранного старта. В интерфейсе возвращённое начало отображается на карте.

Расстояния и время приблизительные. `route.duration_min` включает предположительную длительность соединений с графом; `network_duration_min` и `network_distance_m` относятся только к графу. `door_to_door_verified` всегда false. Неизвестные поля POI — null.

Старые ID объединённых мест разрешаются через `poi_aliases.json`. Сравнение и план удаляют повторные ссылки на одну каноническую запись.

Для `/chat` перед рейсом передайте `airport_transfer_min` и `airport_reserve_min` (каждое 0–240): введённые пользователем оценки дороги и процедур. Чат вычитает их из общего времени; без обоих значений возвращает просьбу указать их, без предложений прогулки. `flight_context` объясняет исходный и оставшийся бюджет. Прогноз пробок/требования авиакомпании не подключены.

Карточка различает `standard_ticket_price`, `child_ticket_price`, `adult_ticket_price`, `ticket_options`, опубликованные `pricing` и средний чек. Документы сети/комплекса помечаются неподтверждёнными для конкретного филиала. `entrance_accessible` отдельно от полной `wheelchair_accessible`; отзыв о тишине хранится как ограниченное утверждение, не проходит строгий фильтр.

Проверка события работает только для существующего `event_id` и разрешённых HTTPS-издателей. `publisher_recheck` содержит время, статус, совпадение даты и URL; отсутствие доступа/данных не считается подтверждением. Даже опубликованное `EventScheduled` не является независимой проверкой проведения.

Ответ `/chat`: у каждого места есть `why` и `what_to_do` (текст Gemini или `null` без модели), `explanation` (`generated`, `basis` — данные места/отзывы/время пути/расписание/погода, `note`), `evidence` (для свойств из запроса: `confirmed`, `supported`, `single_mention`, `mixed`, `contradicted`, `unknown`) и `review_signals` (счётчики и короткие цитаты отзывов 2ГИС). Поле `group_size` (1–10; в `/api/search` и `/api/chat`) задаёт размер компании, иначе чат определяет его по тексту; в ответе чата `group` (`size`, `from_text`), у мест — `group_cost` (`size`, `amount`, `currency`, `basis`: `adult_ticket`, `standard_ticket`, `average_check`, `free_entry`). `events` в ответе чата — анонсы во время прогулки в пешей доступности (`name`, `start`, `end`, `timed`, `venue`, `venue_poi_id`, `walk_min`, `price_from`, `age_group`, `source_url`); у мест-площадок те же записи в `events`. Поле запроса `mini_route` (`true`/`false`, по умолчанию — по смыслу запроса) включает мини-маршрут; в ответе `mini_route` содержит `stops` (с `arrival_offset_min` — через сколько минут от старта прибытие), `legs` (пешие отрезки с геометрией), `total_duration_min`, `walk_duration_min`, `budget_minutes`, а `items` идут в порядке маршрута. `generated_text` показывает, использовался ли текст модели; `generated_facts` всегда false.
